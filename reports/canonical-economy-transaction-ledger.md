# Canonical Economy Transaction Ledger

## Purpose

The calibration ledger is test/report evidence only. It is generated by `npm.cmd run calibrate:economy` into the ignored path `.tmp-playtest/economy-calibration/results.json`; it is not projected to players and does not change production state.

Each event records:

- run ID, round, and operative turn
- operative and character IDs
- stable source ID
- event type and resource namespace
- amount before, signed delta, and amount after
- unique transaction ID
- accepted or rejected status

## Ledger Invariants

- No resource becomes negative.
- Trophy spending uses only the Trophy namespace.
- Every completed-Contract spend is exactly `-3`.
- Every modeled accepted exchange has one start, one spend, and one Artifact selection.
- Salvage loss floors at zero; it is not payment or purchase.
- Sale events are distinct from gains and purchases.
- Artifact selection uses the Artifact namespace and never Salvage.
- Determinism is verified by generating and comparing the complete ledger twice for the same content and seeds.

## Authoritative Transaction Evidence

The production rules are verified outside the model:

- Shop purchase/service resolution verifies seat, phase, stock, affordability, and transaction identity.
- Exact-instance sale removes the item once, applies the authoritative value, and rejects unowned, stale, non-sellable, Artifact, and QA objects.
- Trophy advancement rejects underfunded, capped, invalid, unsafe, and QA-only requests.
- Contract completion archives the exact canonical Contract once and does not replay rewards.
- Artifact exchange requires three distinct stored completed Contract IDs.
- The pending Artifact choice is owner-private and survives reconnect.
- Invalid/wrong-owner/stale Artifact selections are rejected without consuming Contracts.
- Valid confirmation consumes exactly the three Contracts, grants one exact Artifact, and cannot replay.
- TV receives the public exchange outcome but never the private options.

## Salvage Ledger Boundary

`salvage-ledger` has no economy transaction listener. Its canonical behavior is a passive equipped Guile modifier in shops. Therefore automatic loss, sale, Contract reward, Trophy reward, completed-Contract spending, Artifact exchange, reconnect, and rejected transactions cannot trigger a currency benefit. Existing equipment modifier and shop transaction tests cover its only production integration points.

## Reconnect and Privacy

- The uncontended integration suite passed, including reconnect flapping.
- Browser reconnection after Artifact confirmation showed the consumed completed-Contract ledger and granted Artifact without replay.
- Phone options remained private; TV contained no “Choose one Artifact” content.
- Save version remains 2 and legacy v0–v2 import support is unchanged.

## Reproduction

```text
npm.cmd run calibrate:economy
npm.cmd run test:economy-calibration
npm.cmd run qa:economy
```

The raw JSON is intentionally ignored because it is generated evidence, not canonical content or a human playtest record.
