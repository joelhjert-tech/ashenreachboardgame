# Mid-game join closure

## Result

Commit `2046b25` is hardened for standard multiplayer late joining. The server, not the phone, assigns the first configured open seat. A late join is private setup until its operative and starting Contract are confirmed; completion appends that seat to the end of turn order without disturbing the current phase or pending resolution.

Save version remains 2. Unversioned v0, v1, and legacy-compatible v2 imports remain supported.

## Supported and rejected sessions

| Session | Result |
|---|---|
| Active standard multiplayer with a configured unused seat | Accepted |
| Active co-op standard game | Accepted |
| Lobby join | Accepted through the existing lobby lifecycle |
| Single-player active game | Rejected |
| Nemesis Relay active game | Rejected |
| Ended game | Rejected |
| Full configured room | Rejected without changing state |
| Stale or invalid room | Rejected |

## Authoritative lifecycle

1. The phone submits room code and display name only.
2. The server assigns the first non-kicked configured open seat and returns its existing join token.
3. The reserved seat is omitted from `turnOrder` and receives owner-private operative choices.
4. The server validates the selected stable operative ID against the catalog and all occupied seats, then creates the normal starting loadout.
5. The server generates owner-private starting Contract options and validates the selected stable Contract ID against that exact offered set.
6. The final Join Game confirmation appends the seat ID once to the end of `turnOrder` and attaches the selected Contract at progress zero.
7. The current turn, phase, pending effect, battle owner, shop owner, and round remain unchanged. The new operative acts only when normal turn order reaches the appended seat.

The phone cannot author a seat ID, turn-order position, operative object, Contract object, resource amount, enemy roll, or Host Phone authority. The HTTP API now rejects a supplied `seatId` before any room state changes.

## Reservation, cancellation, and races

- The first accepted join reserves the authoritative first open seat; a competing request for the final seat receives `No open seats remain`.
- Two pending players cannot occupy one seat.
- Occupied operative IDs and stale or unoffered Contract IDs are rejected.
- Pending reservations survive disconnect, reconnect with the same token, and v2 save/reload.
- A pending player may leave. The Host Phone may cancel an abandoned pending reservation; this clears setup fields and returns the configured seat to the pool without permanently kicking it.
- A completed join cannot use the pending-release path and cannot append itself twice.
- The full-room phone state changes its primary control to disabled `Room Full` after the authoritative rejection. Editing the room or name permits a new server-validated attempt.

## Host Phone policy

`setupHostSeatId` is assigned only to the first phone during lobby joining. It remains reserved for that seat through disconnection, reconnection, active late joins, and v2 reload. It does not transfer silently, and a late joiner cannot become Host Phone. Room reset/new-game behavior continues to use the existing authoritative setup lifecycle.

## Setup package

Late joiners receive the normal multiplayer starting package generated by `applyStartingLoadout`: 3 Salvage, zero Trophies, no completed Contracts, no Artifact fallback, catalog-defined normal Equipment/followers, zero Wounds, and catalog-defined starting Scars/notes. No catch-up package was introduced. Reconnect restores this state rather than granting it again.

## Battle, phone, and projection behavior

- A late join does not inherit another operative's battle, reaction, or enemy roll.
- Enemy dice remain server-authoritative and resolve once. Existing legacy pending-enemy-roll input remains compatible.
- The joining phone remains in its private setup flow. After completion it follows authoritative Move, Shop, Action, or its own Battle state; tab changes do not submit gameplay actions.
- The TV exposes only the reserved/completed public seat state. Operative and mission option lists remain owner-private.
- Other phones do not receive the joiner's private choices.

## Verification evidence

Focused coverage proves final-seat races, stale operative choices, phase preservation in navigation/resolution/action/broadcast, v2 pending/completed reload, Host Phone retention, starting resources, abandoned reservation release, and battle ownership. Browser QA used a real four-seat co-op server flow with two initial players, separate third and fourth joins, reconnect, and a fifth rejected client.

No gameplay balance, save version, Heat compatibility, battle rules, shop rules, or phone navigation authority changed in this closure.
