# Ashen Reach Quick Reference

## Turn sequence

| Step | What happens |
|---|---|
| Start | Mandatory scenario, operative, Scar/Affliction, and round hooks |
| Navigation | Roll movement; inspect and confirm an exact legal route |
| Sector | Arrival brief; recurring challenges; exploration and Threats |
| Action | Available sector, shop, contract, stabilization, or confrontation action |
| Resolution | Dice, modifiers, result, reactions, consequences |
| Broadcast | Public outcome, cleanup, next seat |

## Movement sequence

1. Use **Roll Movement**.
2. Review server-provided exact-distance destinations.
3. Select a destination to preview it.
4. Review the ordered route and block reasons.
5. Confirm once.
6. Wait for authoritative acceptance.
7. Resolve arrival in this order: sector brief -> recurring challenges -> Threats -> other sector action.

Only authored transitions cross regions. Gates and scenario locks still apply. Preview is not movement.

## Encounter sequence

| Priority | Public role | Normal behavior |
|---:|---|---|
| 1 | Event | Resolves first |
| 2 | Enemy | Battle; may block later cards; may become trophy when defeated |
| 3 | Nemesis | Special public opposition |
| 4 | Encounter | Resolve its typed rule |
| 5 | Asset | Acquire only when legal |

Recurring Hazard/Anomaly Challenges resolve before Threat flow and remain on their sector.

## Test formula

`dice + base attribute + permanent/equipped sources + temporary sources` compared with displayed difficulty.

Attributes: **Command, Grit, Signal, Guile, Forge**.

## Combat sequence

1. Identify operative, opposition, tested attribute, and target.
2. Resolve offered before-roll choices.
3. Roll authoritative dice.
4. Read modifier-source rows.
5. Compare totals.
6. Resolve reroll/replacement if offered.
7. Confirm final result.
8. Resolve prevention and remaining consequences.

The displayed result is authoritative. Do not import a tie rule from another game.

## Shop sequence

1. Be at a shop-capable, unblocked sector.
2. Open available services/stock.
3. Choose buy, sell, service, or skip.
4. Server revalidates location, stock, ownership, cost, and timing.
5. Accepted transaction changes Salvage and inventory atomically.

Automatic Salvage loss is not payment: lose up to the stated amount, minimum 0, and continue resolving the outcome.

## Mission sequence

1. Accept one available contract when no active contract is held.
2. Perform the specifically authored objective.
3. Server advances progress.
4. When satisfied, canonical completion grants reward once, stores the contract ID, clears the active slot, and exposes a new mission opportunity.
5. Repeating an old objective cannot reward the completed contract again.

## End of turn / round

- Finish pending resolution and required actions.
- Server advances to the next seat.
- After all seats, round completion applies round pressure and refreshes round-exhaust effects.
- Charged Artifacts do **not** recharge.

## Timing terms

| Term | Meaning |
|---|---|
| Before roll | Last window before dice are committed |
| Reroll/replacement | After initial result, before final result classification |
| Before consequence | Final result is known; consequence not yet applied |
| First eligible opportunity | First matching server-detected event in the stated limit window |
| Submitted | Request sent; no success yet |
| Accepted | Server validated and committed request |
| Stale | Bound state/reaction has advanced; request changes nothing |

## Status and item glossary

| Status | Meaning |
|---|---|
| Ready | Available when its timing is eligible |
| Exhausted | Used until authored refresh, commonly round completion |
| One Use | Removed/consumed after accepted use |
| Charges X/Y | Exact owned copy has X uses left of Y |
| Depleted | Zero charges; no automatic recharge |
| Recurring | Challenge remains on sector after resolution |
| Locked | Rules prohibit action in current state |
| Temporarily unavailable | Current condition blocks action but may change |

## Cooperative reminders

- Share the scenario objective and Loss Pressure.
- Owner-private choices remain with the owning phone.
- Assistance requires an explicit ability/item prompt.
- No unrestricted resource pool, trading, or revival rule.

## Rivalry reminders

- Keep private agenda text on the owning phone.
- TV shows only authorized public summaries.
- Rivalry does not create a general attack, theft, or trade action.
- The public scenario remains active.

## Pressure glossary

- **Win Progress:** objective completion.
- **Loss Pressure:** scenario defeat track.
- **Global Escalation:** round pressure and difficulty growth.
- **Wounds:** immediate operative harm.
- **Scars/Afflictions:** lasting conditions.
- **Deep Relic Search:** pay 1 Salvage at an eligible Relic Dealer to reveal four options.
